# torch-onnx 2.15.0

The standalone exporter now uses native torchlib implementations and follows the
PyTorch 2.15 development baseline. The version jumps to 2.15.0 to align its major
and minor components with that baseline; future releases increment the exporter
patch number independently. Python 3.11 or newer is required.

## Highlights

- Default export opset is 28. Explicit older opsets remain supported through the
  existing version-conversion path.
- PyTorch is not version-pinned. Compatibility CI covers stable releases from
  the preceding year; unvalidated or incompatible installations warn once and
  still attempt export. See [PyTorch compatibility](../pytorch-compatibility.md).
- Native translations use `op.constant`, incremental symbolic shape inference
  and public ONNX IR schemas. `ONNXProgram.optimize()` uses the standalone
  optimizer.
- Transformers integration covers tiny BERT, Qwen3, MoE, hybrid-attention and ViT
  models, dynamic inputs, generation caches and save/reload. Useful operator
  patches and custom lowerings are integrated into torchlib; pure FX graph
  repairs remain in Transformers. See [integration details](../transformers.md).
- Public `torch.onnx.ops` custom symbolic operators, multi-output lowerings,
  Attention and RotaryEmbedding have compatibility coverage.
- Tensor-based embedding-bag, boolean index updates and masked-scatter lowerings
  reduce Sequence operations or intermediate storage where measured beneficial.
  Differential fuzzing includes model-architecture recipes and crash isolation.
- RoPE fusion repairs use public `rewriter.RewriteRule` APIs. Runtime-only
  operator workarounds are excluded; an explicit metadata-only exception mirrors
  function-local opset imports for ORT's nested-function inliner.

## Runtime boundaries

An exported ONNX graph can be valid even when the installed runtime lacks its
kernels. ORT 1.32 has limitations for several newer schemas and for inverse,
onesided DFT. Tests use explicitly selected reference execution or schema checks
for those cases. No unconditional bf16 Conv-to-fp32 cast is included. See
[opset support](../opsets.md) and the [native operator audit](../transformers-native.md).

## Validation

Local verification covers the broad exporter regression suite, targeted function
and control-flow regressions, PyTorch 2.10 compatibility, model-recipe fuzzing,
and 21 integration cases against the checked-out Transformers exporter. CPU
performance measurements are case-specific and do not establish GPU coverage.
