# torch-onnx 2.15.0

**torch-onnx is an experimental standalone alternative to PyTorch's built-in ONNX
exporter.** It uses `torch.export` for model capture, with its own ONNX translation
backend. This release migrates the ONNX Script torchlib operator implementations
to direct ONNX IR construction, fixes export and numerical issues, and adds
integration coverage for torchvision, torchao and Transformers.

## How it differs from the built-in exporter

- **Native ONNX IR translations.** Built-in operator lowerings construct ONNX IR
  directly through `GraphBuilder` and `TranslationContext`, replacing the ONNX
  Script function-based translation path. Operator implementations can be fixed
  and released independently of PyTorch.
- **No separate FX type-promotion pass.** Native lowerings own dtype promotion,
  casts and computation precision. The exporter no longer reruns an FX graph
  solely for that type-promotion pass. Type promotion itself is still required
  and is handled explicitly by the translations.
- **Native custom lowerings.** `register_custom_translation` lets users construct
  ONNX IR with the same API as built-in translations. Existing ONNX Script
  custom translation callables remain supported through a compatibility adapter.
- **Incremental inference and validation.** The builder uses
  `onnx-shape-inference` for intermediate dtype and symbolic-shape inference, and
  ONNX schemas to validate operator inputs, attributes and target-opset types.
- **A tailored optimization pipeline.** Export-time optimization and
  `ONNXProgram.optimize()` use the same pipeline, with exact, dtype-aware
  arithmetic rewrite rules. ONNX Script remains a dependency for reused
  optimization, fusion, version conversion and custom-translation compatibility.

Use `torch_onnx.export(...)` directly, or `torch_onnx.patch_torch()` to route
existing `torch.onnx.export(...)` calls through this backend.

## Ecosystem support

- **torchvision:** native translations for NMS, ROI Align, position-sensitive
  ROI Align and DeformConv2d, with actual-package export and numerical tests.
- **torchao:** affine quantization/dequantization paths for int8/uint8,
  int16/int32 and selected float8 formats, plus a real int8 weight-only Linear
  frontend. Supported types and opsets vary; this does not cover arbitrary packed
  layouts or every `torchao.quantize_` configuration. See the
  [operator support matrix](../optional-operators.md).
- **Transformers:** integration with its real `OnnxExporter`, including dynamic
  inputs, generation caches and save/reload. Tiny BERT, Qwen3, MoE,
  hybrid-attention and ViT models are tested. Useful operator patches and custom
  lowerings are implemented natively; downstream FX repairs remain in
  Transformers. This is coverage of the tested models, not every architecture.
- **Custom ONNX operators:** support for `torch.onnx.ops.symbolic`,
  `symbolic_multi_out`, and the public Attention/RotaryEmbedding helpers.

Torchvision and torchao are optional and registered lazily. Neither is required
or imported merely by importing `torch_onnx`.

## Correctness and graph improvements

Representative fixes include integer floor/trunc division without lossy floating
conversion; CrossEntropy label smoothing; stable BCE-with-logits evaluation;
DOUBLE constant precision; mixed-dtype and reduction handling; and einsum
ellipsis broadcasting. Exact optimizer rules preserve nonzero normalization
epsilon, near-one scales and floating signed-zero behavior. The
[issue inventory](../reported-issues.md) also records remaining limitations.

EmbeddingBag uses tensor Loop scan outputs instead of Sequence accumulation and
an O(N+B) auxiliary mapping instead of an N-by-B mask. Boolean index updates,
masked scatter and non-affine RMSNorm also use simpler lowerings where measured
beneficial. [CPU benchmarks](../performance.md) and the
[native operator audit](../transformers-native.md) describe the tested cases;
these are not whole-model or GPU speedup guarantees.

Differential fuzzing, model-architecture recipes, crash isolation and replay
artifacts complement directed numerical, dynamic-shape and empty-input tests.

## Opsets, compatibility and migration

- The default is **opset 28**. Explicit older targets retain their decompositions
  and version-conversion path. Newer targets use operators such as Swish,
  Attention, CumProd and BitCast where applicable. Opset 29 coverage is a
  development-schema preview; see [opset support](../opsets.md).
- The `torch` dependency is **not pinned**. Compatibility CI covers stable
  releases from the preceding year, currently 2.10 through 2.15. Unvalidated or
  incompatible installations warn once and still attempt export.
- Python **3.11+** is required. This package targets the modern exporter;
  legacy TorchScript export (`dynamo=False`) and the old standalone
  `dynamo_export` / `ExportOptions` APIs are unsupported.
- Dynamic-shape APIs, control flow, InputObserver, fake-tensor export and deferred
  weights remain available as familiar workflows; they are not claimed as
  standalone-exclusive capabilities. Capture still depends on `torch.export`.
- Version numbers now follow the development PyTorch major/minor. The jump from
  the previous release series to **2.15.0** establishes that baseline; exporter
  patch releases advance independently of PyTorch patch releases.

A valid ONNX graph may require a newer runtime or reference execution. Runtime
kernel limitations are not generally patched into operator lowerings. One
explicit metadata-only exception mirrors function-local opset imports into the
model for ORT's nested-function inliner. No unconditional bf16 Conv-to-fp32 cast
is added. Reduced-precision, packed quantization and GPU support are limited to
explicitly documented coverage.
