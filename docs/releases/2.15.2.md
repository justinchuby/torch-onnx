# torch-onnx 2.15.2

This release expands the standalone native-IR exporter's operator coverage and
fixes scalar precision, Boolean sorting, and exporter API contracts. Models using
non-4D attention, the reported special functions, and window factories can now
export through this backend. The experimental native-IR architecture introduced
in [2.15.0](2.15.0.md) remains the foundation; these changes are implemented in
this project's torchlib and exporter.

## Attention, special functions, and windows

- **Non-4D scaled dot product attention:** rank-2 and higher inputs use native math
  lowering, including 3D self/cross-attention, broadcast masks, dynamic shapes,
  empty inputs, and grouped-query attention along the head axis. Rank-4 inputs
  retain fused ONNX Attention where supported by the target opset.
  [PR #241](https://github.com/justinchuby/torch-onnx/pull/241).
- **Fourteen special functions:** add ATen and prims lowering for `hypot`,
  `erfinv`, `i0`, `i1`, `lgamma`, `digamma`, `spherical_bessel_j0`, `ndtri`,
  `bessel_j0`, `bessel_j1`, `gammainc`, `gammaincc`, `nextafter`, and `zeta`,
  starting at opset 18. The implementations construct ONNX IR directly, with
  tensor-carried Loop state for iterative algorithms and no Sequence operations
  or SciPy runtime dependency.
- **Window factories:** support the missing default, periodic, and custom-parameter
  overloads for Hann, Hamming, Blackman, Bartlett, and Kaiser. Correct Hamming's
  default coefficients to PyTorch's `0.54/0.46`, and cover empty/singleton lengths.
  Native IR supports dynamic window lengths; PyTorch capture can still specialize
  integer factory lengths.
- **Boolean sort/argsort:** use schema-valid integer TopK inputs and restore
  Boolean values, preserving INT64 indices and stable tie ordering.

Special-function, window, and Boolean fixes are in
[PR #242](https://github.com/justinchuby/torch-onnx/pull/242).

## Constants, errors, and exporter correctness

- **Construct constants directly in the final dtype.** The new
  `op.cast_like(value, other)` helper creates Python literals using `other.dtype`
  when known, reusing the graph-local constant cache. It avoids an intermediate
  Constant/CastLike pair and preserves DOUBLE literals such as `1.0000000001`.
  Existing IR values and unknown target dtypes retain ONNX CastLike semantics.
  Torchlib uses the helper throughout, including embedding, factories, scalar
  arithmetic, and attention. You can also use `op.constant(value, dtype=...)`
  in custom translations.
  [PR #243](https://github.com/justinchuby/torch-onnx/pull/243).
- **Reuse PyTorch ONNX exception classes.** Catching the corresponding
  `torch.onnx` exporter errors also catches this backend's exceptions; preserve
  exception identity and pickling through the public aliases.
  [PR #239](https://github.com/justinchuby/torch-onnx/pull/239).
- **Fix uncovered exporter contracts.** Parse CLI Boolean values correctly
  (`--report False` disables reporting), forward `--external_data` to saving,
  enforce declared ONNX types in union annotations, reuse multi-output raw-IR
  producer values for `getitem`, and accept zero-output operators.
  [PR #240](https://github.com/justinchuby/torch-onnx/pull/240).

## Validation and compatibility

The compatibility suite now lives in `tests/compatibility/`. CI uses pytest's
standard directory discovery, so new files are included automatically without
an explicit file list, custom marker collector, or importing baseline-only test
modules. All **599 compatibility tests passed locally on both PyTorch 2.10.0
and 2.15.0**. The annual stable-release CI matrix is unchanged.
[PR #245](https://github.com/justinchuby/torch-onnx/pull/245).

Project-wide coverage now includes all source files and combines main-suite,
optional-package, development-opset, Transformers, and version-matrix results.
Expanded tests exercise numerical behavior, serialization, schemas, diagnostics,
and failures. See [coverage methodology](../testing-coverage.md).

Special-function tests cover poles, tails, broadcasting, empty tensors, dynamic
shapes, and serialization. Independent high-precision fixtures validate large
incomplete-gamma tails. Iterative special functions have input-dependent costs;
gamma series/fractions are capped at 2000 iterations. Reference execution checks
spec-valid cases where ORT lacks kernels or changes signed zero. This release
does not add runtime-specific semantic workarounds. See the
[reported-issue inventory](../reported-issues.md) for numerical/runtime boundaries.

The default remains **opset 28**. Python 3.11+ is required, and the `torch`
dependency remains unpinned. Upgrade with:

```bash
python -m pip install --upgrade torch-onnx
```
